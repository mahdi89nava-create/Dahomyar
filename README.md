# دهم‌یار ۷.۰ — PWA / Offline First

## اجرا
این پروژه را روی HTTPS یا localhost اجرا کنید. باز کردن مستقیم `index.html` با `file://` برای Service Worker مناسب نیست.

## نصب Android
Chrome/Edge را باز کنید → منوی مرورگر → Install app / Add to Home screen.

## نصب Windows
Chrome یا Edge → آیکون Install در نوار آدرس یا منوی مرورگر → Install.

## قابلیت‌ها
- Offline-first و کش فایل‌های اصلی
- تشخیص آنلاین/آفلاین
- صف IndexedDB برای داده‌های قابل‌صف و هوک همگام‌سازی
- پنل کنترل وضعیت اتصال، کش، صف و آپدیت
- manifest + service worker
- آیکون 192/512 و splash screen داخلی
- آپدیت Service Worker و بررسی نسخه
- حفظ رابط و ابزارهای موجود دهم‌یار ۶.۰

## نکته فنی
Google Login، دیتابیس ابری، Mahdi AI و آمار آنلاین هنوز به backend واقعی نیاز دارند. این نسخه زیرساخت PWA و offline queue را آماده می‌کند و برای درخواست‌های واقعی باید endpoint امن سرور به `DehomYarOffline.queue()` متصل شود.


## نسخه ۱۲ — مرکز یادگیری و امنیت
- مرکز یادگیری برای ریاضی، هندسه، فیزیک، شیمی، فارسی، عربی، انگلیسی، دینی، جامعه‌شناسی، تاریخ/جغرافیا، نگارش و سواد دیجیتال
- مرور موضوعی، آزمونک‌های کوتاه، برنامه‌ریز مطالعه و آمار محلی
- مهدی AI با تاریخچه گفت‌وگو در همان نشست، حالت‌های آموزشی بیشتر و پاسخ جایگزین محدود در نبود سرویس AI
- محدودسازی درخواست‌های AI، بررسی Origin درخواست‌های دارای Origin، هدرهای امنیتی، محدودیت حجم درخواست، اعتبارسنجی امضای فایل‌های تکلیف و محدودیت حجم بسته‌های ZIP
- بررسی خودکار نحو JavaScript و تست‌های پایه مسیر AI در GitHub Actions

### راه‌اندازی سرویس AI واقعی
برای فعال شدن پاسخ‌های مولد واقعی، در تنظیمات محیطی سرویس Render این متغیرها را به‌صورت Secret/Environment Variable تنظیم کنید:
- `AI_API_URL`: آدرس HTTPS سرویس سازگار با قالب درخواست این پروژه
- `AI_API_KEY`: کلید API (فقط در سرور؛ هرگز داخل HTML یا GitHub قرار ندهید)
- `AI_MODEL`: نام مدل مورد استفاده سرویس

بدون `AI_API_URL` و `AI_API_KEY`، مهدی AI از پاسخ‌های محلی و محدود استفاده می‌کند؛ این حالت جایگزین مدل زبانی واقعی نیست. تنظیمات ارائه‌دهنده‌های مختلف ممکن است به adapter اختصاصی نیاز داشته باشد.

### یادداشت امنیتی
هدرهای امنیتی و کنترل‌های پایه اضافه شده‌اند، اما رابط قدیمی هنوز از handlerهای inline استفاده می‌کند؛ به همین دلیل CSP فعلی برای سازگاری شامل `unsafe-inline` است و نباید آن را محافظت کامل در برابر XSS تلقی کرد. مرحله بعدی سخت‌گیری بیشتر، حذف handlerهای inline، آزمون امنیتی روی محیط staging و بررسی تنظیمات واقعی دیسک Render است.


## نسخه ۱۹ — حساب‌ها و فضای جداگانه کلاس‌ها
- ثبت‌نام و ورود دانش‌آموز با نام کاربری و رمز عبور؛ رمزها با scrypt هش می‌شوند.
- حساب دانش‌آموز به یکی از کلاس‌های ۱۰۱، ۱۰۲، ۱۰۳ یا ۱۰۴ متصل می‌شود.
- پنل نماینده هر کلاس با کد جداگانه‌ای که فقط مدیر اصلی می‌تواند ایجاد/تعویض کند.
- نماینده فقط برای کلاس خودش تکلیف، پیوست مجاز (PDF، تصویر یا Word تا ۸ مگابایت) و اطلاعیه منتشر می‌کند.
- تکالیف و اطلاعیه‌های اختصاصی از API کلاس با نشست معتبر و بررسی کلاس محافظت می‌شوند.
- حساب‌ها، کدهای نمایندگی و اطلاعیه‌ها در فایل‌های DATA_DIR نگهداری می‌شوند؛ روی Render باید دیسک پایدار متصل باشد.
- کد نماینده فقط هنگام ساخت/تعویض یک بار نمایش داده می‌شود؛ آن را خصوصی نگه دارید. تعویض کد قبلی را باطل می‌کند.
- فعلاً بازیابی رمز خودکار با ایمیل/پیامک پیاده‌سازی نشده؛ مدیر اصلی باید در فرایند پشتیبانی حساب را مدیریت کند.
